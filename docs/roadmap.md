# 実装順序

## 1. 前提の確定

- 普段の利用端末、必要なメール操作、Gmail から変えたい体験を確認する。アドレス種別と利用者数は確定済み。
- 送信元スタックと 5 つの重要通知カテゴリを、実メールのヘッダーで試す。
- 予約などの曖昧なメールを対象に、Workers AI の分類精度、入力範囲、遅延、利用量を小さな試作で評価する。
- OAuth の公開状態・必要スコープをテスト用 Google Cloud プロジェクトで確認する。
- Gmail API で受信箱全件を段階的に索引化する時間・API 使用量と、添付ファイルの扱いを小さな試作で測る。

## 2. 最小版

- Cloudflare Workers + Hono + React のプロジェクトを作り、Static Assets と API を同一オリジンで動かす。
- 本人限定の OAuth 接続、暗号化したトークン保存、セッション、ログアウトを実装する。
- 受信一覧、スレッド詳細、検索、既読・未読、アーカイブ、ゴミ箱を実装する。
- HTML メールの安全な表示とプレーンテキスト表示を実装し、外部画像・リンク・危険な要素の扱いを検証する。
- 確定した整理モデルに沿った一覧・分類操作を実装する。
- メタデータの初回取り込み、差分同期、履歴切れからの再同期を実装する。
- 画面を開いている間の自動更新と手動更新を実装し、失敗時の表示と API 使用量を検証する。
- 添付ファイルのダウンロードを実装する。
- メール本文をサーバー保存しないこと、認証・メール操作失敗時の動作を検証する。

## 3. 日常利用へ

- 実際のメールで表示・操作を評価し、必要な UI とキーボード操作を決める。
- 配信解除、ラベル操作、通知の優先度を決める。
- Cloudflare と Google の運用・費用、バックアップや復旧手順を確認して公開する。
