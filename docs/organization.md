# 整理モデル

## 目指す見方

メールを大きく「プロモーション」と「重要な通知」に分けて見る。Gmail の受信トレイやカテゴリは分類の手がかりに使えるが、このメーラーの分類そのものは利用者が調整できるようにする。

### プロモーション

- プロモーションメールを**送信元ごとのスタック**にまとめる。スタックには送信元、未読数、最新の件名と日時を示し、開くとその送信元のメールを新しい順に見る。
- 初期の送信元キーは正規化した `From` のメールアドレス。表示名だけではまとめない。同じ企業の複数アドレスをまとめる操作は後で追加できるようにする。
- スタックはメッセージ単位で集計し、開いた先では該当メッセージを含むスレッドを読めるようにする。複数メールからなるスレッド全体を無条件にプロモーション扱いしない。
- スタック内では1通ずつ確認・操作できるようにする。それに加えて、送信元スタック単位で「まとめて既読」「まとめてアーカイブ」「まとめてゴミ箱へ移動」を実行できるようにする。対象は実行時にそのスタックに含まれる受信箱内のメール全件とし、ページ表示に依存させない。各操作の対象件数と範囲を実行前に示す。後から届くメールまで自動処理するルールとは分ける。
- 同じ送信元から来る購入確認や配送通知までプロモーションに巻き込まない。**メールの種類を判定した後に送信元で束ねる**。
- Gmail の `CATEGORY_PROMOTIONS` は初期判定の手がかりにするが、利用者が「プロモーションではない」「プロモーションにする」と修正できるようにする。[Gmail のシステムラベル](https://developers.google.com/workspace/gmail/api/guides/labels)
- 将来、スタックから配信解除できるようにする。送信元と配信リストは同一とは限らないため、解除はスタック全体への一括操作ではなく、対象リストを確認して実行する。

### 重要な通知

初期のカテゴリ候補は次の 5 つ。カテゴリ間に固定の優先順位は設けず、重要な通知をまとめて新しい順に見られるようにする。名称は実メールを見て調整する。

| カテゴリ | 入れたいメールの例 | 誤分類で注意すること |
| --- | --- | --- |
| クレジット利用速報 | カード利用の即時通知 | カード会社の広告を混ぜない |
| 配送通知 | 佐川急便、ヤマト運輸などの配達・不在・集荷通知 | なりすまし対策として表示上の差出人名だけで判定しない |
| ショッピングのお知らせ | 注文、決済、発送、返品などの連絡 | セール案内はプロモーションへ分ける |
| 契約・サブスクのお知らせ | 更新、請求、料金変更、契約条件など | サービスからの宣伝は分ける |
| 予約のお知らせ | 交通、宿泊、飲食店、イベントなどの予約確認・変更・キャンセル | 予約サイトの広告やおすすめを混ぜない |

同じメールが複数カテゴリに該当することは許す。見逃したくない通知を誤って隠すより、重複表示を許容する。分類不能なメールは通常の受信一覧に残す。カテゴリに含める条件は利用者が確認・修正できるようにし、判定理由も表示する。

重要な通知のカテゴリ一覧には受信箱内のメールだけを表示する。既読もアーカイブするまでは表示し、アーカイブするとカテゴリから外す。分類情報は残し、アーカイブ済み一覧と検索から参照できるようにする。

## 分類方法（暫定）

1. Gmail のカテゴリラベルとメールのヘッダー（`From`、`Subject`、`List-Id` など）を取得する。ヘッダー取得には Gmail API の `METADATA` 形式を使える。[messages.get](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/get)
2. 個別メールに対する利用者の修正があれば、それを最優先する。
3. 利用者が設定した送信元・件名などの明確なルールを適用する。Gmail のカテゴリラベルは判定の手がかりとし、重要通知を誤ってプロモーションへ固定しない。
4. ルールだけで判断できないメールを Workers AI の候補とする。AI の導入自体は試作の結果で決める。
5. 判定できないメールは通常の受信一覧に残す。

上記は動作順序の案。実装前に、実メールの差出人や件名を本人が確認してルールを作る。カード会社や配送会社の「公式アドレス」をこちらで決め打ちしない。

### Workers AI による分類（検討中）

- 予約通知など、送信元・件名ルールだけでは見分けにくいメールの分類候補として [Workers AI](https://developers.cloudflare.com/workers-ai/) を評価する。個別修正と明示的なルールを優先し、AI は曖昧なメールだけの補助判定に使う。全受信メールを AI に送る方式は採らない。
- Workers AI に送るなら、差出人・件名・必要なヘッダーに加えて、そのメールの本文全体を使う方向。HTML 本文は安全にテキストへ変換してから送る。分類のために取得した本文は D1 やログへ保存しない。添付ファイルは分類に渡さない。
- モデルの入力上限を超える本文は、黙って切り詰めて「全文で判定した」扱いにしない。分割して判定する方法を検証するか、「不明」として利用者に示す。
- モデルの返答は定義済みカテゴリと「不明」だけを受け付け、誤った形式や失敗は「不明」として通常の受信一覧に残す。AI の結果だけでアーカイブ、既読、ゴミ箱移動は行わない。判定理由と利用者の修正操作を表示する。
- AI への入力・出力はアプリ側で本文として永続保存しない。分類結果を保存する場合はモデルと分類方式のバージョンを記録し、修正や再分類ができるようにする。実装前に実メールで精度、遅延、利用量、料金を測る。[Workers AI のデータ利用](https://developers.cloudflare.com/workers-ai/platform/data-usage/) / [料金](https://developers.cloudflare.com/workers-ai/platform/pricing/)

重要通知カテゴリと送信元スタックは、日付で区切らず受信箱に残っているメールを対象にする。古いメールでも受信箱にある限り分類から外さない。初回同期は新しいメールから段階的に取り込み、完了するまで件数が暫定であることを画面に示す。受信箱全件の取り込み時間と Gmail API 使用量を試作で測る。

## データの置き場所（暫定）

- Gmail: メール本文・添付・Gmail ラベルの正本。
- D1: カテゴリ定義、分類ルール、送信元のまとめ方、個別メールの分類修正。受信箱の分類・スタック表示のため、メッセージ ID・スレッド ID・送信元アドレス・日時・Gmail ラベル・分類に必要な最小限のヘッダーを索引として保持する。本文・添付は保存しない。
- Gmail ラベルへの書き戻しは初期版では行わない。独自分類はこのメーラー内の表示上の状態とする。必要になれば同期を追加する。

ルールの変更を過去のメールにも反映できるよう、分類結果だけを正本として保存しない。個別修正は Gmail のメッセージ ID に結びつける。メールが削除された場合の古い修正情報は定期的に整理する。

分類を修正するときは「この1通だけ」と「同じ送信元の今後のメールにも適用」を選べるようにする。後者は新しい分類ルールとして保存し、対象となる送信元と条件を確認してから有効にする。同じ送信元が広告と取引通知を送る場合があるため、必要なら件名や `List-Id` などで条件を絞る。過去のメールへの一括適用は別の操作とし、初期版での必要性を確認する。

初回は受信箱をページごとに取り込み、以後は Gmail の `history.list` で差分を取得する。履歴 ID が古くなって 404 が返る場合は受信箱を再同期する。検索と本文表示は引き続き Gmail API を直接使う。[Gmail 同期ガイド](https://developers.google.com/workspace/gmail/api/guides/sync)

## 迷惑メール

このメーラーに迷惑メール一覧を設けない。Gmail API の通常の一覧・検索では Spam / Trash を含めない設定を使い、迷惑メールの確認や誤判定からの復旧は Gmail の画面で行う。[threads.list](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.threads/list)

## 将来の配信解除

`List-Unsubscribe` と `List-Unsubscribe-Post` ヘッダーを確認し、[RFC 8058 のワンクリック解除](https://datatracker.ietf.org/doc/rfc8058/)に対応するメールでは、対象のリストと送信先を利用者に示してから解除する。対応しないメールには外部サイトへのリンクを表示する方法を検討する。メール本文中の任意の URL を自動で実行しない。Gmail の「購読の管理」と同じ解除範囲を Gmail API から再現できるとは想定しない。[Gmail の購読管理](https://support.google.com/mail/answer/15621070?hl=ja)
