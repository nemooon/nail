# 目的と前提

## 目的

既存のメールアドレスを維持し、受信・整理では Gmail の Web UI を使わずに済む、本人が使いやすい Web メーラーを作る。送信・返信は Gmail で行う。アプリケーションは Cloudflare 上で動かす。決まった設計事項は `docs/` に記録する。

最優先の改善対象は、Gmail とは異なるメールの整理方法。プロモーションを送信元で束ね、重要な通知を用途別に見る。[整理モデル](organization.md) に詳細を記録する。

## 確定した前提

- メールアドレスは個人の `@gmail.com` アカウント。
- 最初の版は本人専用で、接続先アカウントは 1 つ。複数利用者向けの公開サービスは想定しない。
- PC とスマートフォンの両方を日常的に使う。どちらでも受信確認、検索、整理を完結できるようにする。
- Gmail は主に受信に使い、会話がスレッドになることは少ない。初期画面では1通ごとの確認と整理を優先する。
- 読み終えたメールはアーカイブして受信箱から片付ける。既読にしただけで自動的にアーカイブはしない。
- Gmail の受信画面から離れて独自の整理画面を使う。`@gmail.com` の受信・送信とメール保管は引き続き Gmail に依存し、送信・返信時には Gmail の画面を使う。

## 最初の利用体験

1. 自分の Google アカウントで接続する。
2. 受信箱を1通ずつ新しい順に見る。必要なときはクレジット利用速報、配送通知、ショッピング、契約・サブスク、予約のお知らせを専用の一覧で見る。
3. プロモーションを送信元ごとのスタックで見る。
4. アーカイブ、ゴミ箱も見る。迷惑メールの一覧は設けない。
5. スレッドを読み、分類を修正し、既読・未読、アーカイブ、ゴミ箱への移動を操作する。
6. Gmail の検索構文でメールを探し、添付ファイルをダウンロードする。

初期版から HTML 本文を安全に表示できるようにする。プレーンテキスト本文も表示する。HTML 表示では危険な要素の除去、外部画像の初期ブロック、リンク先の扱いを設計・検証する。アプリ内での送信・返信・下書き作成は対象外とする。配信解除、複雑なラベル管理、複数アカウント、オフライン利用、通知は後続候補とする。

初期版では送信済みメールと下書きの一覧も設けない。必要なときは Gmail で見る。

## 成功条件

- 普段の受信確認と整理、検索を Gmail の Web UI を開かずに完了できる。
- サーバー側にメール本文を永続保存せず、認証情報はブラウザーに渡さない。
- Google API の認証が切れたときは安全に再接続でき、メール操作が失敗したときは成功と誤表示しない。

## 確認待ち

- 現在のメール量・整理習慣。
- カテゴリに入れたい実際の送信元や件名の例。実メールを共有せず、本人がルールを設定する形でもよい。
