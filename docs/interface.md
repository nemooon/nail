# 画面設計のたたき台

## 画面の流れ

1. 認証前: 接続する Google アカウントと権限を示し、本人だけがログインできる。
2. 最初の画面: 受信箱を1通ずつ新しい順に表示する。重要な通知は独立した一覧で確認でき、カテゴリ別にも絞り込める。既読もアーカイブするまでは一覧から見られる。プロモーションの送信元スタックにも移動できる。
3. 一覧: 1通ごとを基本とし、既読・未読を同じ一覧に新しい順で表示する。各行には差出人、件名、短いプレビュー、日時、未読状態、添付の有無を表示する。分類の理由と修正操作も示す。
4. 詳細: 選んだメールの HTML またはプレーンテキスト本文を読み、同じスレッドにほかのメールがあれば前後の会話にも移動できる。外部画像は初期状態で読み込まず、必要な場合に明示的に表示する。既読・未読、アーカイブ、ゴミ箱への移動を行う。
5. 検索: Gmail の検索構文をそのまま利用し、結果からメール詳細に移る。

## 初期の操作原則（暫定）

- 最初の画面は受信箱とする。重要な通知はナビゲーションから開けるようにし、大きな要約カードは置かない。
- 日常的に多くのメールを確認できるよう、余白と装飾を抑えた密度の高いツール画面にする。PC では最初のメールを詳細ペインに表示する。
- メール一覧はペインの左右いっぱいに広げる。画面見出しと検索欄には操作しやすい余白を残す。
- 検索欄は PC では見出し・更新操作と同じ列に置き、スマートフォンでは短い入力欄として見出しの直下に置く。
- 送信元のロゴを使える場合は一覧と詳細に表示し、ロゴがない場合は頭文字に戻す。表示名だけでロゴを紐づけない。ロゴの取得元と安全な扱いは実装前に決める。
- 受信したメールの確認と整理を主要な動線に置く。送信・返信は Gmail で行い、アプリ内に作成画面を設けない。
- 既読にしただけで一覧から消さない。未読は文字の強調と明確な印で区別し、色だけに頼らない。
- アーカイブを一覧と詳細のどちらからも実行できるようにする。実行後は受信一覧から外し、アーカイブ済みの一覧と検索から再び開けるようにする。
- 重要な通知もアーカイブすると重要通知一覧とカテゴリ一覧から外す。分類情報は保持し、アーカイブ済み一覧と検索から再び開けるようにする。
- プロモーションの送信元スタックには、個別メールの操作に加えて「まとめて既読」「まとめてアーカイブ」「まとめてゴミ箱へ移動」を置く。実行前に対象件数と範囲を示し、ゴミ箱への一括移動は確認を挟む。
- 分類の修正時には「この1通だけ」と「同じ送信元の今後にも適用」を選べるようにする。今後にも適用する場合は、送信元と追加条件を確認してから保存する。
- 画面を開いている間は自動で新着を確認し、手動更新ボタンも置く。更新中、最終更新時刻、失敗時の状態を表示する。
- 新着確認から本文を読むまでの操作を短くする。
- ゴミ箱への移動などの操作結果と失敗状態を明確にする。
- PC とスマートフォンの両方を主要な利用端末として扱い、どちらでも受信確認、検索、整理を完結できるようにする。
- スマートフォンでは一覧からメール詳細へ遷移する単一ペインを基本とする。
- デスクトップではナビゲーション、一覧、メール詳細を横に表示する。一覧と詳細はそれぞれ独立してスクロールし、片方を読んでももう片方の位置を変えない。画面幅が狭い場合は単一ペインへ切り替える。
- 重要な操作はキーボードでもできるようにする。ただしショートカットの割り当ては実際の利用習慣を聞いて決める。
- Workers AI の初期版への採用は試作後に決める。採用する場合はヘッダーと本文全体を使い、添付は送らない。分類案と判定理由、修正方法を利用者に示す。

## 未決

- 重要な通知のカテゴリ表示形式。
- デスクトップでの詳細ペインの必要性と、画面幅ごとの切り替え位置。
- 同じスレッド内の複数メールを一覧にも個別表示するか、最新の1通に集約するか。
- テーマ、密度、文字サイズなどの好み。
